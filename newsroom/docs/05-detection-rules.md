# 05 检测规则 d1 与评分 s1

代码：`nr/normalize/episodes.py`、`nr/detect/rules.py`、`nr/detect/at_risk.py`、`nr/events/service.py`、`nr/facts/builder.py`（评分与门禁）。阈值在“系统管理 → 规则与预算 → detect”里可改（写入审计），下表是初始值，需要用真实数据调整。

## 1. 持仓回合

同一交易员、同一币种，从看到某个方向开始，到平仓或反手为止，是一个回合。

| 原始事件 | 处理 |
|---|---|
| `first_seen` | 开回合，`start_kind=first_seen`、`start_precision=unknown`（**永远不是开仓**） |
| `open` | 开回合；OKX 报告了开仓时间时精确，否则为窗口 |
| `flip` | 结束旧回合（flipped），开新回合 |
| `increase` / `decrease` | 累计加 / 减仓额、峰值；没有已知回合时建 `reconstructed` 回合（开始时间未知） |
| `close` | 结束回合，结束时间为窗口 |

## 2. 事件类型

| 类型 | 触发 | 合并 |
|---|---|---|
| `whale_open` | 开仓后名义价值 ≥ 100 万美元（HL）/ 30 万（OKX） | 每回合一个 |
| `flip` | 反手后名义价值 ≥ 同上 | 每个新回合一个 |
| `whale_add` | 回合累计加仓 ≥ 100 万（HL）/ 30 万（OKX），或跨过档位 1/5/10/25/50/100M | 未报道前合并到同一事件；报道后只有更高档位才产生新事件（同一故事的续集） |
| `underwater_add` | 浮亏方向加仓且仓位 ≥ 50 万 | 同上 |
| `whale_close` | 平仓额 ≥ 100 万 / 30 万 | 每回合一个 |
| `liquidation` | 平仓价在最后报告强平价 0.5% 以内或越过，且 ≥ 25 万 → 疑似 | 每回合一个；之后用交易所记录升级为确认，**同一事件出新版事实包** |
| `near_liquidation` | 新鲜持仓距强平 ≤ 3% / 1.5% / 0.5%，且 ≥ 100 万 | 每回合每档一个 |
| `notable_trader_move` | 25 万–阈值之间的开仓 / 反手 / 加仓 | 交易员有已验证战绩才保留，否则淘汰 |

“已验证战绩”= 风格 `verified`，或择时 `q ≤ 0.1` 且样本 ≥ 30，或跟单评级 A。

**为什么不只看金额**：同样 300 万美元，一个账户值 3000 万的钱包是 0.1 倍，账户值 50 万的钱包是 6 倍；一个有 34 个完整周期、最大仓位从未超过 50 万的交易员突然开 300 万，比一个常年开 3000 万的钱包更反常。评分里分别有“相对账户”和“相对自身历史”两项。

## 3. 可解释评分 s1（满分 100）

每一项都存 `{points, max, note, inputs}`，在事件详情页逐项显示。

| 项 | 满分 | 规则 |
|---|---|---|
| 绝对规模 | 25 | 25 ×（log10(名义 / 交易所门槛) / 2 + 0.25），1 倍门槛≈6，10 倍≈19，32 倍以上满分 |
| 相对账户 | 15 | 仓位 / 账户值，2 倍满分；账户值不可靠（`aggregate_account` 等）时 0 分并注明 |
| 相对自身历史 | 10 | ≥ 历史最大完整周期 2 倍得 10，≥1 倍得 5；无完整档案 0 分 |
| 交易员战绩 | 20 | 已验证风格 8、显著择时 6、跟单 A 6 / B 3、90 天 TWR 为正且可靠性高 4 |
| 风险 | 15 | 杠杆 ≥20 加 5、距强平 ≤5% 加 5、浮亏加仓加 5；强平确认 15 / 疑似 8 |
| 市场相关度 | 10 | BTC/ETH/SOL/HYPE 4（同币种聚集加分在 Phase 2） |
| 连续性 | 5 | 所属故事已有发布 2 |
| 扣分 | — | 观测窗口超过 4 小时 -5；交易员数据过期 -10 |

≥ 30 进入候选；≥ 50 且 AI 开启时自动交给 AI 总编辑。分数只决定排序和是否值得人看，**不决定能否发布**。

## 4. 可信度门（硬条件）

任何一条成立，事件就是 `blocked`，不能进入评估、分派、审核或发布，直到数据恢复（每 15 分钟自动重新核验）：

| 代码 | 含义 |
|---|---|
| `SOURCE_STALE` | 最近健康快照超过 10 分钟、Feed 不可达，或该交易所雷达为 stale |
| `SYNC_BACKLOG` | 最近一次成功同步超过 10 分钟，或积压超过 5000 行 |
| `CONTEXT_UNAVAILABLE` | 拉取交易员上下文失败 |
| `TRADER_STALE` | 持仓类事件，但该交易员的轮询已过期 |
| `CONTRADICTED_BY_CONTEXT` | 持仓类事件，但当前持仓里已经没有这个仓位（或方向相反） |
| `MISSING_PRICE` | 触发观测没有标记价 |
| `FIRST_SEEN_ONLY` | 开仓类事件，但回合起点只是首次观测 |

不阻断但限制措辞的情况写成事实包约束（见 06）。

## 5. 去重保证

- 同一条原始观测重复同步：`source_event` 唯一约束，插入为空操作。
- 同一仓位被反复轮询：不产生新的原始事件（AlphaScope 只在仓位变化时写 `market_event`）；产生了也会落到同一个回合、同一个 `dedupe_key`。
- 连续加仓：未报道前合并；报道后只有升档才是新闻。
- 近强平：每回合每档一次。
