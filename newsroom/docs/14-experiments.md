# 14 内容实验与编辑评分

## 1. 为什么先做实验

2026-11-23 的全链路审查结论是：稿件只会复述仓位，瓶颈在证据和记忆，不在写作。对照事实（06 §1）、故事记忆和提示词 v2 是针对这个问题的改动。在把 v2 设为默认之前，先用盲评实验确认它是否让稿件明显变好。实验没有通过，就不推广。

## 2. 实验设计（`nr/experiments/contrast_ab.py`）

| 项 | 内容 |
|---|---|
| 样本 | 最近 48 小时、与账号交易所一致的事件，每个仓位只取一个。按类别分层：开仓/加仓 10、浮亏加仓 10、接近强平 5、平仓/强平 5（按样本数等比缩放）。某层不够时，用其他类别补足 |
| 准备 | 每个样本先刷新事实包（会用到 Feed 的上下文额度）；门禁不通过的跳过 |
| A 组 | 去掉对照事实的事实包（等同 facts-1）+ 提示词 v1 + 没有故事记忆 |
| B 组 | 完整事实包 + 提示词 v2（开头写“这次有什么不同”、最多三个数字、`why_now`、`open_question`、`lede_fact_ids`）+ 故事记忆 |
| 不变量 | 同一账号、同一记者角色、同一模型；两版都是试写稿，不改变事件状态，不能提交审核 |
| 盲评 | 页面只显示“稿件 1 / 稿件 2”，左右顺序随机，对应关系只保存在服务器上。评审按信息增量、开头、证据、可发布性各打 1–5 分，选出更好的一篇（可选“差不多”），并标记有误导的稿件 |
| 结果 | 总编辑随时可看；其他评审评完所有已生成的稿件后才能看 |

成功标准（同时满足）：B 胜率 ≥ 65%（平局按半票）；B 的守卫通过率不低于 A；B 被标误导的次数不多于 A；B 多用的 token ≤ 50%（单价为 0 时只能比较 token）。

停止条件（满足任一）：
- 有两类以上对照事实的样本不足 40%：说明数据覆盖不够，应先扩大成交档案覆盖，不要继续调写作。
- 有 10 票以上，且 B 胜率低于 55%。

## 3. 怎么做

1. 确认 AI 角色已经绑定可用模型，并在“测试模型”中通过。
2. 导航“内容实验”→“发起实验”：选账号（决定写作风格和平台长度规则）、模型、样本数，然后点开始。worker 会先抽样，再排队生成两版。页面会自动刷新，直到全部生成完。
3. 至少两位编辑分别打开“去盲评”，逐对打分。
4. 打开“结果”，对照成功标准做决定：
   - 通过：在“系统管理 → AI 角色”里把 reporter 和 reporter_* 的提示词版本改为 2（EIC 也可以改为 2，以记录未解问题）。
   - 停止：保持 v1，按停止原因处理。

命令行也可以查看：`sudo newsroom/start.sh logs worker` 可以看到抽样结果（`experiment_create` 任务），失败的那一组会把原因写在实验列表里。

## 4. 日常评分

编辑室每篇稿件的当前版本都可以打 1–5 分，并勾选标签（有新信息、开头好、证据扎实、有故事性、语气不对、角度不对、有误导），每人每个版本保留一条评分。盲评的分数也会写入同一张表（标记为盲评）。这些评分是以后周度质量报告的数据来源（按事件类别、角度、风格、模型汇总）。

## 5. 数据表（迁移 0009）

- `news_story.open_questions`：故事的未解问题（EIC v2 输出，最多保留 10 条）。
- `article_version.why_now`、`open_question`、`lede_fact_ids`：v2 稿件的附加字段。
- `draft_rating`：版本评分，`(article_version_id, user_id)` 唯一。
- `experiment_pair`：每个事件一对，记录两组的版本 id 或失败原因、随机顺序；`experiment_vote`：每人每对一票。
