# 04 · 指标与评分体系

每个指标都写明：**定义、数据依赖、适用范围、异常处理、可信度**。没有足够数据的指标显示"数据不足"，不填充估计值。

## 1. 收益指标

### 1.1 资金流调整收益（已实现，`backend/app/quant/returns.py`，版本 `r1`）

数据：portfolio 的 `(t_i, AV_i, PnL_i)`，其中 PnL 是 Hyperliquid 计算的累计盈亏，**不包含充值、提现和划转**。

```
ΔPnL_i = PnL_i − PnL_{i−1}
flow_i = (AV_i − AV_{i−1}) − ΔPnL_i            # 外部资金流入(+)/流出(−)
r_i    = ΔPnL_i / (AV_{i−1} + 0.5 · flow_i)     # Modified Dietz，假设资金流发生在区间中点
TWR    = Π(1 + r_i) − 1
MDD    = min_k ( I_k / max_{j≤k} I_j − 1 ),  I_k = Π_{i≤k}(1 + r_i)
PnL MDD(USD) = 累计 PnL 曲线的最大回撤（不依赖分母）
```

| 窗口 | 来源序列 | 覆盖判定 |
|---|---|---|
| 30D | month | 存在早于窗口起点的锚点 |
| 90D / 180D / 365D | allTime 的子集 | 同上；开户时间晚于窗口起点 → `covered=false`，显示"数据不足" |
| 全部 | allTime | 从首次入金开始 |

**异常处理**
- 资本基数 < $10 的区间跳过（不除以接近 0 的分母），并在 notes 记录数量。
- 单期 r ≤ −100% 截断为 −100%，并标记 `wipeout_period`。
- |flow| > 50% × 账户规模的区间记为"大额资金流"，此时中点假设误差大。
- 有效区间 < 3 个时不给出 TWR / MDD。

**可信度**
- `low`：区间太少、出现清零区间，或大额资金流 / 被跳过的区间超过 25%。
- `medium`：中位点间隔超过 24 小时（粗粒度）、存在大额资金流，或历史短于窗口。
- `high`：其他情况。

**已知局限**：粗粒度序列看不到区间内部的回撤，MDD 会被**低估**，所以粗粒度结果只用于初筛，不进入正式评分。

### 1.2 其他收益指标（P1，基于逐笔成交 + 资金流水）

| 指标 | 定义 | 依赖 |
|---|---|---|
| 已实现净盈亏 | Σ closedPnl − Σ fee + Σ funding | fills, funding |
| 未实现盈亏 | 来自 clearinghouse 快照 | account/position snapshot |
| MWR（资金加权收益） | 令 Σ CF_t/(1+IRR)^t = 0 的 IRR（CF 为充提 + 期末净值） | transfer_event + equity |
| 单位风险回报 | 净盈亏 / 平均保证金占用 | fills + position snapshots |
| 盈利月份比例 | 月度 TWR > 0 的月份数 / 月份总数（至少 3 个月） | equity 序列 |

**ROI 口径**：界面上同时出现官方 ROI（口径未公开）和自算 TWR 时，必须分别标注"官方 / 自算"。永远不用"当前净值 / 首次观测净值"代替收益率。

## 2. 风险指标

| 指标 | 定义 | 最低数据要求 |
|---|---|---|
| 最大回撤 / 平均回撤 / 回撤持续时间 / 恢复时间 | 基于 TWR 指数 | 日频或更细的资金流调整序列；粗粒度时标注"可能低估" |
| 波动率 / 下行波动率 | 日收益标准差 × √365；下行只算负收益 | ≥ 60 个日收益 |
| Sharpe / Sortino | 年化收益 / 年化（下行）波动率，无风险利率取 0 | 同上；序列间隔不规则时**不计算** |
| Calmar | 年化收益 / \|MDD\| | ≥ 180 天 |
| 单笔最大亏损、最大连续亏损 | round_trip 的净盈亏 | 完整 round trip ≥ 20 |
| 风险集中度 | 单币种名义敞口占比的 HHI | position snapshots |
| 杠杆风险 | 名义敞口 / 净值的分布与趋势，距强平价的最小距离 | position snapshots |
| 强平历史 | liquidation_event 次数与损失 | fills / ledger |

## 3. 交易质量指标（P1）

统计单位是**完整的 round trip（开仓到平仓）**，不是成交记录。

| 指标 | 定义 |
|---|---|
| 胜率 | 净盈亏 > 0 的 round trip 数 / 完整 round trip 数（附 Wilson 95% 置信区间） |
| 平均盈利 / 平均亏损 / 盈亏比 | 均值之比 |
| Profit Factor | Σ盈利 / \|Σ亏损\| |
| 期望值 | 胜率 × 平均盈利 − (1 − 胜率) × 平均亏损；附 bootstrap 置信区间 |
| 盈利集中度 | 最大 1 笔、前 5% 交易贡献的净盈亏占比 |
| 持仓效率 | 实现盈亏 / MFE（需要 K 线） |
| 进出场时机 | 进场后 N 分钟的价格变化相对随机进场的分位数 |
| 执行质量 | 吃单比例（crossed）、平均手续费率、相对中间价的滑点 |

## 4. 稳定性指标

- 周 / 月收益分布、正收益周期占比；
- 去掉最好的 1 笔和最好的 1 周后剩余收益（"去掉运气后还剩多少"）；
- 不同市场状态（market_regime）下分别计算的期望值；
- 滚动 30 天期望值、杠杆与回撤的趋势（Alpha 衰减雷达的输入）。

## 5. 交易能力评分（Skill Score，P1）

**结构**：先算可解释的分项，再按可配置权重合成。权重起点如下，必须经过第 7 节的验证后才能调整。

| 分项 | 初始权重 | 主要输入 |
|---|---|---|
| 盈利能力 | 25% | 资金流调整收益、期望值、Profit Factor |
| 风险控制 | 25% | MDD、下行波动、单笔最大亏损、杠杆趋势、强平 |
| 稳定性 | 20% | 正收益周期占比、去极值后收益、收益集中度 |
| 决策质量 | 15% | 盈亏比、持仓效率、时机分位 |
| 环境适应性 | 15% | 跨市场状态的期望值离散度 |

**计算方式**
1. 每个分项按**同类钱包**（同层级、相近资金规模）计算百分位，再映射到 0–100。
2. 收缩：`score_adj = w · score + (1 − w) · 同类中位数`，`w = n / (n + k)`，其中 n 为有效样本（round trip 数或有效区间数），k 为先验强度（初始 30）。
3. 置信度 = f(样本量、数据覆盖率、可信度等级)；置信度不足时状态为**"证据不足，暂不评级"**，不显示总分。
4. 输出：总分、分项分、置信度、同类排名、加分原因、扣分原因（例如"收益主要来自 1 笔交易（占 63%）"）。

**禁止**：总分不得直接使用 ROI；任何单一分项的权重不得超过 35%。

## 6. 跟单可复制性评分（Copyability Score，P2）

| 分项 | 计算 |
|---|---|
| 延迟衰减 | 在每笔成交上加 2s / 5s / 30s / 5min 延迟，用随后的 1m 价格重新计价，收益保留比例 |
| 成本敏感度 | 计入跟随者的手续费（吃单）、半个买卖价差、估算滑点后的收益保留比例 |
| 持仓周期 | 持仓越短，可复制性越低（主观阈值需验证） |
| 流动性与容量 | 交易标的日成交额、交易规模 / 订单簿深度；估算跟单资金上限 |
| 执行方式 | TWAP、高频挂单、大量撤单 → 难以复制 |
| 前瞻验证 | 影子跟单真实结果与理论结果的差距（最重要，时间越长权重越大） |

示例：高频做市型账户可能 Skill 高、Copyability 低；持仓数天、交易主流币的趋势交易者可能 Copyability 高。

## 7. 验证方法（防过拟合）

1. **时间滚动验证**：用 t 之前的数据计算评分 → 观察 t 之后 30/90 天的资金流调整收益与回撤。评分有效的标准：高分组的样本外风险调整收益显著高于低分组（单调性检验 + bootstrap）。
2. **名单战绩**：每个名单冻结后按固定规则跟踪，公开样本外表现。
3. **基准**：随机抽取同层钱包、官方 ROI 前 N 名作为对照组；评分必须跑赢 ROI 前 N 名才有意义。
4. **敏感性分析**：权重 ±10% 时排名的稳定性（Kendall τ）。
5. **不以明星为模板**：禁止根据少数已知优秀钱包反推权重；验证集与调参集按时间切分。

## 8. 数据质量检查（P1 起每次运行）

- fills 推算的已实现盈亏 vs portfolio pnlHistory 的差额（对账误差 > 5% 标记）；
- 排行榜 30D PnL vs portfolio month PnL（不一致通常意味着子账户汇总）；
- 净值异常跳变而 PnL 不变 → 应能在 ledger 中找到对应资金流；
- 零成交量但 PnL 变化 → 被动盈亏；
- 新出现的字段或窗口 → 记录到 ingest_run.stats（已实现）。
