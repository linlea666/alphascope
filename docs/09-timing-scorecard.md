# 09 · 多级别节奏与时机评分（"抄底逃顶"日历）

> 目标：从超短到大周期，**按级别分别**统计交易员在"位置"和"节奏"上的判断是否准确，例如是否买在阶段低点、卖在阶段高点、在拐点附近反手；并按近 7 天、30 天、90 天、全部滚动统计。只有在某个级别上**显著、持续、能兑现、能复制**的交易员，才进入模拟跟单候选池。

与 [08 大周期研究](08-swing-event-research.md) 的关系：08 用大波段找出候选并抢救成交数据；本文把它扩展成**覆盖所有级别、持续更新**的评分体系，并作为模拟跟单的入口。

## 1.1 T1 / T2 实施结果（2026-11-16，已编码、已测试）

**T1 币安 K 线**（`backend/app/ingest/binance_ingest.py`）
- 19 个币已导入 1 分钟线并聚合出 15m / 1h / 4h / 1d：BTC、ETH、SOL 从 2025-01-01 起，其余（归档钱包交易最多的币）从 2026-06-01 起。
- BTC 共 984,960 根，正好是 684 天 × 1,440 分钟，没有缺口；每个文件都校验了 SHA256；可以重复运行，只补缺失的文件。
- 币种映射用 Hyperliquid 的真实成交价和币安同一分钟的收盘价对比，比价中位数都在 0.997–1.002 之间。CASHCAT 等 Hyperliquid 独有的币，以及 HIP-3、现货，都标为"不可用 / 不支持"。
- 存储：K 线表 1.4 GB。worker 每 6 小时增量一次。

**T2 仓位重建**（`backend/app/research/positions.py`）
- 实测发现两个关键问题，已经修正：
  1. **成交编号 `tid` 不按时间顺序**。同一毫秒内的多笔成交，要按"成交前仓位"串成链来排序；修正后断档从 123,850 降到 4（约 18 万条成交）。
  2. **现货不能串链**（币本位手续费、转账、小额兑换都会改变余额），也不是杠杆仓位，所以排除。永续合约（含 HIP-3）全部能串上。
- **与交易所对账**（`alphascope reconcile`）：在有归档成交的永续合约上，30 个持仓与实时持仓完全一致，不一致 0 个。另有 12 个持仓早于归档开始、之后没有交易，标为"早于归档"，这属于覆盖范围限制，不是错误。
- 成交同步未完成的钱包也会重建：未平仓周期只算到最后一笔已归档成交，页面标"数据截止"，不当作仍在持有。
- 实例：某个 93% 交易 BTC/ETH 的钱包，分级别后的结果是：
  - 超短 88 个周期，胜率 10%，净亏 $17.4 万；
  - 短线净亏 $4.7 万；
  - 波段净赚 $47.6 万；
  - 大周期净赚 $37.7 万。

  不分级别时，它只是一个"总体赚钱"的钱包。这正说明评分必须按级别做，跟单也应该只跟它擅长的级别。

## 1.2 T3 实施结果（2026-11-17，已编码、已测试）

**时机评分**（`backend/app/research/timing.py`，版本 `t1`，worker 每 3 小时重算一次）
- 每个决策在它所属仓位周期的级别上评分，各级别使用的数据：

  | 级别 | K 线 | 评估窗口 |
  |---|---|---|
  | 超短 | 15 分钟 | ±4 小时 |
  | 短线 | 1 小时 | ±2 天 |
  | 波段 | 4 小时 | ±7 天 |
  | 大周期 | 日线 | ±30 天 |

  K 线优先用币安，没有的用 Hyperliquid 自己的 K 线（HIP-3 股票 / 商品、Hyperliquid 独有币也已开始记录）。
- 位置分：买入 =（窗口最高 − 价格）/（最高 − 最低），卖出 =（价格 − 最低）/（最高 − 最低），按名义价值加权。评估窗口还没走完的决策标为"待定"，不评分。
- 显著性：把这个钱包的全部决策时间整体循环平移 500 次（保持间隔和方向）作为运气基准，算出 p 值；再对所有钱包按级别、窗口分别做 Benjamini–Hochberg 校正，得到 q 值。超额 = 位置分 − 基准均值，并按样本量收缩。
- 拐点精准率 / 召回率、顺势比例（持仓方向与该级别当前波段一致的时间占比）、各级别净盈亏也一并计算。
- 统计窗口（7D / 30D / 90D / 全部）的有效性矩阵和最低样本量与第 2 节一致；不满足的显示"样本不足"或"不统计"。
- 页面：
  - **节奏榜** `/timing`：可按级别、窗口、币种组切换，可只看显著的；
  - 交易员页：**时机评分卡**（级别 × 窗口）和**节奏日历**（每天、每个级别的平均位置分，标出命中拐点的次数）。

**关键价位交易**（`/zones`，`backend/app/api/zones.py`）
- 查询"谁在某个价格区间、某个时间段内开过多 / 空仓"，以及这些仓位的结局：已实现盈亏、平仓均价、是否仍持有（估算浮动盈亏）。可以再加第二个条件，取两者的交集。
- 预设（对应本轮 BTC 周期）：
  - BTC 57,000–69,999 做多（7–9 月）；
  - BTC 84,000–88,000 做空（9–10 月）；
  - 两头都做对。
- 每次结果都会写明覆盖范围：多少个归档钱包能回溯到查询起点。

**扩大成交归档（宏观扫描队列）**：为了覆盖更多"在 6 万多做多"的人，加入净值 ≥ $1 万、无噪声标记、近 30 天活跃的 B 层钱包，按换手率从低到高排队，默认 1,500 个，排在大周期候选之后。换手低的钱包，8 月的成交大概率还在 API 窗口内。

**首轮结果（本机数据，12 个已重建钱包）**：67 组评分达到样本要求，3 组显著（q < 0.1）。整体平均超额接近 0，说明大多数交易员的买卖时机和随机差别不大。显著的那几组超额也很小（0.005–0.007）：样本大时，小优势也能被检出，所以榜单同时显示超额大小和 q 值。服务器上随着归档推进，样本会持续增加。

## 1.3 第四轮：波段持仓者、K 线回放、按币种和买卖分开评分（2026-11-17）

用户反馈：关键价位查询选出的大多是在低位开仓、几百美元波动就平掉的短线单，不是想要的"拿得住"的大周期交易员。为此新增：

**波段持仓者** `/holders`（`backend/app/api/holders.py`、`backend/app/research/holders.py`）
- **方法 1：开仓区间 → 平仓区间。** 一个仓位周期的加权开仓均价落在开仓区间内，并且至少 50% 的峰值仓位在平仓区间内平掉（仓位周期现在按决策记录了开平仓明细）。空单如果仍然持有，且当前价格已在目标区间内，也算达标，按浮盈计。预设：
  - BTC 63k–68k 做多 → 83k–87.5k 平；
  - BTC 82k–87.5k 做空 → 62k–72k 平。
- **方法 2：整段行情捕获率**（版本 `c1`）。在每段大级别行情中，按小时用实际持仓盯市，算出：
  - 顺势时间占比和逆势时间占比；
  - 捕获率 = 盯市盈亏 /（峰值名义仓位 × 行情幅度）。

  中途换手、分批进出都会计入，弥补方法 1 只看单个周期的不足。日线拐点会用小时线精确到极值出现的那个小时；成交覆盖不完整的（开始晚于行情起点，或同步还没到行情终点）标为"部分覆盖"。

**K 线回放**（交易员页）：选定币种和周期（15m / 1h / 4h / 1d），把他的每次买卖用 B / S 标在 K 线上，同时标出该级别的局部高低点（H / L），可以向前、向后翻页。用来直接核对"是不是真的抄在底、卖在顶"。

**节奏榜增强**
- **按单个币种出分：** 某个币在该级别的决策数达到最低样本量，才出这个币的分。
- **买卖分开：** 分别统计买入落在窗口最低 20% 的比例、卖出落在最高 20% 的比例，并给出随机平移下同一比例的实测基准。**实测随机基准约 9%，不是 20%**：价格大部分时间处在区间中部，随机下单很少正好落在极端位置。可以按"两头都准"排序，即取两者中较小的那个。
- **挂单比例：** 挂单成交（未主动吃单）超过 80% 的账户标为"挂单型"，可以一键排除。这类账户低买高卖是挂单方式天然带来的，不代表判断能力。

**修复**：持仓路径以前按"决策所在的小时"对齐，比如 02:10 的成交会被当成从 02:00 起就持有。现在改为按精确时间对齐：只有开始时间不早于成交时间的小时才计入，单元测试已覆盖。

## 2. 级别阶梯（版本 `ladder-v1`）

| 级别 | 波段阈值（BTC 基准） | 计算用 K 线 | 典型持仓 | 位置评估窗口 | 有效统计窗口 |
|---|---|---|---|---|---|
| **超短** | 1.5% | 1m / 15m | < 4 小时 | ±4 小时 | 7D、30D |
| **短线** | 4% | 1h | 4 小时 – 3 天 | ±2 天 | 7D（样本够时）、30D、90D |
| **波段** | 8% | 4h | 3 天 – 3 周 | ±1 周 | 30D（样本够时）、90D、180D |
| **大周期** | 15% | 1d | > 3 周 | ±1 月 | 180D、365D、全部 |

- 波段由 ZigZag 在各级别 K 线上客观划分，和 08 用的是同一套算法，带版本。
- 其他币种的阈值按波动率换算：`阈值(币) = 阈值(BTC) × 该币 90 天已实现波动率 / BTC 90 天已实现波动率`。否则山寨币每天都会触发"超短拐点"。
- "有效统计窗口"之外的组合不出分，界面显示"样本不足"，不用其他窗口外推。

## 3. 评分单位：从成交到"决策"

1. **仓位路径**：每笔成交都带 `startPosition`，加上本笔的方向和数量，就是成交后的精确仓位，不需要完整历史（与 08 阶段二共用）。
2. **决策**：同一币种、同一方向、间隔在 15 分钟内的连续仓位变化合并成一个决策，类型为开仓 / 加仓 / 减仓 / 平仓 / 反手。拆单、TWAP 和部分成交不会被重复计数。
3. **仓位周期**：从开仓到平仓（或反手）为一个周期，按持仓时长归入某个级别。周期里的每个决策都在**它所属的级别**上评分，同时记录相邻级别的分数作为参考。
4. **权重**：每个决策按名义价值 / 当时净值加权。小仓位抄到底、大仓位追在高点，结果应该是负分。

## 4. 指标

所有指标按 **交易员 × 币种组（BTC/ETH、主流币、山寨币、HIP-3）× 级别 × 统计窗口** 计算。

| 指标 | 定义 | 回答的问题 |
|---|---|---|
| **位置分**（抄底逃顶精度） | 买入：`1 − (p − 窗口最低价)/(窗口最高价 − 窗口最低价)`；卖出 / 做空：`1 − (窗口最高价 − p)/(最高价 − 最低价)`。窗口为该级别的 ±评估窗口。名义加权平均后，转换为相对**随机时点基准**的分位数 | 买点是不是接近阶段低点、卖点是不是接近阶段高点 |
| **拐点精准率** | 反转类决策（多单止盈 / 开空 / 空单止盈 / 开多）中，命中该级别拐点的比例。命中 = 时间在相邻波段时长的 20% 以内，且价格在波段幅度的 25% 以内 | 他的抄底逃顶动作有多少是真抄到、真逃到 |
| **拐点召回率** | 他在该币种上活跃期间出现的拐点中，被他命中的比例 | 大机会出现时，他是不是经常在场 |
| **节奏一致度** | 持仓方向与该级别当前波段方向一致的时间占比，按敞口加权 | 是不是顺着这个级别的节奏做 |
| **捕获率** | 实际拿到的走势 / 满仓拿住整段的走势 | 判断对了，拿住了多少 |
| **兑现** | 该级别仓位周期的净盈亏（扣除手续费和资金费） | 准不准最后要看赚没赚到钱 |
| **显著性** | 置换检验：保持决策数量和间隔，把时间整体随机平移 1,000 次，得到"运气分布"并计算 p 值；对所有交易员按级别、窗口做 Benjamini–Hochberg 多重检验校正 | 是能力还是碰巧 |

**最低样本**：超短 ≥ 30 个决策，短线 ≥ 15，波段 ≥ 6，大周期 ≥ 3 次拐点机会。不够时显示"样本不足"，同时给出已有样本数。

**收缩**：样本少的分数会向同级别中位数收缩（与 04 的 Skill Score 一致），避免 3 次碰巧全中就排到榜首。

## 5. 日历统计

### 5.1 交易员节奏日历（交易员页）

- 4 行对应 4 个级别；列为日期（超短、短线按天，波段按周，大周期按月）。
- 格子颜色 = 该时段的位置分位，圆点大小 = 决策数；最上方标出市场在该级别的拐点。
- 点击格子：展开当时的 K 线，叠加他的开平仓点和该级别的拐点，可以直接看出"抄底是不是真的抄在底上"。

### 5.2 市场拐点日历（大周期页扩展）

每个级别的每个拐点一行，列出命中这个拐点的钱包，并标出他们的历史精准率。用来回答"谁抄到了 11/15 61,970 的底"、"谁在 9/21 87,471 附近转空"，并显示这个人过去在同级别是不是一贯如此。

### 5.3 滚动节奏榜

- **筛选维度：** 级别（超短 / 短线 / 波段 / 大周期）× 窗口（7D / 30D / 90D / 全部）× 币种组。
- **榜单列：** 位置分位、拐点精准率 / 召回率、决策数、兑现盈亏、显著性（q 值）、持续性（见 6.2）、所属跟单漏斗阶段。
- **默认规则：** 只显示样本达标且 q < 0.1 的钱包；可以切换到"全部"查看。

## 6. 回测与验证

### 6.1 事后评分（上面的指标）

位置分和拐点用到了决策**之后**的价格，所以它们只能用来**评价过去**，页面上统一标注"事后评分"。

### 6.2 前瞻持续性检验（选人用）

这一步决定"筛出来的人能不能拿来跟单"：

- **滚动检验：** 每周 t，只用 t 之前 30 天的数据计算各级别评分，再看下一个 30 天的评分和收益。
- **两个统计量：** 每个级别的排名相关性（rank IC），以及前 10% 的人下期仍在前 30% 的比例。
- **准入条件：** 只有排名相关性连续 ≥ 8 周显著大于 0 的级别，才用于选人。如果某个级别的"准"本身不持续（比如超短级别），这个级别的榜单只展示、不进入选人。
- **个人持续性：** 近 ≥ 3 个滚动窗口都在同级别前 30%。

### 6.3 跟单复制回测（用币安 1 分钟线）

- **模拟方式：** 对每个决策假设延迟 5 秒 / 30 秒 / 2 分钟 / 10 分钟后才跟上。成交价用之后 1 分钟线的开高低收插值，再计入半个点差、按成交量估算的冲击成本和手续费。
- **输出：**
  - 时机保留率 = 跟单后的位置分与盈亏 / 原交易员的；
  - 各级别、各延迟下的收益曲线。
- **预期：** 超短级别的优势大多会被延迟吃掉，这正是要量化的东西。
- **数据精度：** 1 分钟以内的延迟精度有限。币安期货最细只有 1 分钟线；现货有 1 秒线，可以作为近似参考。以后自建节点后可以用逐笔成交数据替代。

## 7. 模拟跟单候选漏斗

```
全部 B 层钱包（约 1.4 万）
 └ 08 大周期初筛 / 潜力引擎 → 成交归档（A 层）
    G0 数据：成交覆盖评估窗口，未被截断
    G1 技能：至少一个级别显著（q < 0.1）且样本达标
    G2 持续：该级别通过前瞻持续性检验（6.2）
    G3 兑现：该级别的仓位周期净盈利 > 0，捕获率达标
    G4 可复制：30 秒延迟下时机保留率 ≥ 60%，标的流动性足够
    G5 风控：杠杆、强平记录、最大回撤在阈值内
 → 模拟跟单候选池（按级别分组：短线 / 波段 / 大周期为主，超短大多停在 G4）
 → 影子跟单（前瞻验证，P2）
```

每个钱包在交易员页显示它停在哪一关、为什么没通过。阈值都写在配置里并带版本，先用历史数据检验后再定稿。

## 8. 数据方案（引入币安 K 线）

| 项目 | 设计 |
|---|---|
| 来源 | `market_candle` 增加 `source` 字段（`hyperliquid` / `binance_um`），主键改为 (source, coin, interval, t) |
| 历史回补 | `data.binance.vision` 的 U 本位永续月度 / 日度压缩包，逐个校验 SHA256；从 2025-01 开始 |
| 存储粒度 | 主流币存 1 分钟线；15m / 1h / 4h / 1d 在本地由 1 分钟线聚合，保证各周期一致 |
| 币种范围 | BTC、ETH、SOL，加上已归档成交中名义价值排名前 20 的币种（动态更新） |
| 每日增量 | 日度压缩包在第二天发布；当天的数据，能访问实时 API（服务器）时用实时 API，不能访问时（本机返回 451）用 Hyperliquid 自己的 K 线补上 |
| 币种映射 | Hyperliquid 币名 → 币安合约 + 倍数（如 `kPEPE` → `1000PEPEUSDT`）；自动校验价格比例中位数和相关性，不一致的映射不使用 |
| HIP-3 与 Hyperliquid 独有币种 | 币安没有，只能用 Hyperliquid K 线（从现在起自己记录，已在运行） |
| 价差监控 | 每天计算两边价差；某时段价差 > 30 个基点时，该时段改用 Hyperliquid K 线评分 |
| 规模 | 1 分钟线每币每年约 52.5 万行；25 个币 × 2 年约 2,600 万行，约 3–5 GB。按月分区；分析量变大后改用 Parquet + DuckDB |
| 使用条款 | 只使用公开行情数据；页面展示派生指标和图表，不提供原始数据下载 |

## 9. 防误判

| 情况 | 为什么会误判 | 处理 |
|---|---|---|
| 做市、网格账户 | 被动挂单天然"买在低点、卖在高点" | 用净仓位变化定义决策，不用单笔成交；挂单比例 > 80% 且双边频繁的账户单独归类为"做市型"，不进节奏榜 |
| 摊平补仓（DCA） | 多次买入里总有一次在最低点 | 按名义价值加权的位置分 + 拐点精准率 |
| 小仓位抄底、大仓位追高 | 只看次数会高估 | 名义加权 |
| 多重检验 | 数千钱包 × 4 级别 × 4 窗口，总会有人看起来很准 | Benjamini–Hochberg 校正 + 最低样本 + 收缩 |
| 事后定义拐点 | 位置分用到了未来价格 | 只用于评价；选人只用前瞻检验的结果 |
| 7 天窗口 | 大级别样本太少 | 有效性矩阵之外不出分 |
| 子账户 | 主地址只是实体的一部分 | 子账户合并之前，汇总账户不进入候选池 |

## 11. 本轮新增的创新机会

| 名称 | 价值 | 成本 | 优先级 |
|---|---|---|---|
| **O 多级别共振选手** | 同时在 ≥ 2 个级别（如波段 + 大周期）显著准确的人很少，决策少、质量高、延迟不敏感，最适合跟单 | 低（评分的副产品） | **高** |
| **P 节奏错配预警** | 交易员最近的决策从自己擅长的级别漂移到别的级别（例如亏损后从波段变成频繁的超短操作），往往是失控的前兆；可以并入 Alpha 衰减雷达 | 低 | 中 |
| **Q 拐点前夜持仓** | 高评分交易员在各级别拐点前的合计敞口，研究它是否领先价格；验证前只做研究，不作为信号展示 | 中 | 中 |
| **R 主动买卖量背景** | 币安 K 线自带主动买入量，可以研究"他是不是在主动卖盘衰竭时抄底"，用来解释能力的来源 | 低 | 中 |
