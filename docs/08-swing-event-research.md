# 08 · 大周期与事件敏感交易员研究

> 目标：找出在 BTC 大涨和大跌中**提前或较早站对方向、拿住主要行情、并在转折附近及时退出或反手**的钱包，并判断这是可重复的能力还是一次运气。

> 多级别（超短 → 大周期）的节奏与时机评分、日历统计、币安 K 线回测和模拟跟单候选漏斗，见 [09](09-timing-scorecard.md)。

## 1. 先确认事件（2026-11-16 用 Hyperliquid BTC 日线核对）

| 阶段 | 时间 | 价格 | 说明 |
|---|---|---|---|
| 底部 | 7/1 | 57,768 | 本轮涨段的真正起点（不是 8 月） |
| 筑底横盘 | 8/1–8/17 | 62.2k–64.5k | 8/1 低点 62,237 |
| **突破主升** | 8/17–8/24 | 64.5k → 79k | 一周 +22%，最考验"敢不敢追/有没有提前在场" |
| 高位整理 | 8/24–9/14 | 78k–82k | 考验"拿不拿得住" |
| 第二波 | 9/14–9/21 | 78k → **87,471** | 本轮最高点 |
| 双顶 | 9/21–10/2 | 87.5k / 87.2k | 考验"顶部有没有减仓或反手" |
| 阴跌 | 10/2–11/9 | 87k → 75k | — |
| **急跌** | 11/9–11/15 | 75.3k → **61,970** | 一周 −17% |

系统用 ZigZag 算法客观划分波段（`backend/app/research/swings.py`，版本 `z1`）：大波段阈值 15%，小波段阈值 7%，都基于日线高低点。2025 年以来共有 16 个大波段、62 个小波段。上表中的阶段对应小波段，本轮的两个大波段是 **#15 涨 +51.4%（7/1–9/21）** 和 **#16 跌 −29.2%（9/21–11/15，暂定）**。

**为什么不手工挑日期**：手工选择"8 月到 9 月"这类区间，会不自觉地挑出对结论有利的窗口。算法划分加上版本号，能保证每次评估都用同一把尺子。波段只用来**事后评估**交易行为，不作为交易信号。

## 2. 核心思路

### 2.1 分开评估两种能力

| 能力 | 问题 | 指标 |
|---|---|---|
| **方向判断** | 仓位方向和行情方向是否一致、是否提前 | 方向一致时间占比、建仓提前量、转折附近的反手 |
| **收益兑现** | 判断对了，钱有没有赚到手 | 捕获比例、持仓坚持度、退出点离顶/底的距离 |

很多人方向判断是对的，但仓位太小、拿不住，或者在回调里被洗出局；也有人赚到了钱，靠的却是高杠杆加一次运气。两种能力都要看。

### 2.2 必须按币种归因（实测教训）

第一阶段的探针显示：只看收益曲线时，"涨段和跌段都赚钱"排在最前面的 12 个钱包里，**只有 2 个真正靠 BTC 方向赚钱**。其余的盈利来自 SUI、ZEC 等山寨币，以及 Hyperliquid 上的 HIP-3 股票/商品永续（如 `xyz:CL` 原油、`xyz:GOLD`、SK 海力士）。所以候选钱包至少要分成三类：

| 类型 | 特征 | 用途 |
|---|---|---|
| **方向型宏观交易员** | 两个方向都赚，且 BTC/ETH 净敞口方向与波段一致 | 本研究的核心目标 |
| **全天候 / 市场中性** | 不论涨跌都赚，但与 BTC 方向无关（做市、套利、其他资产） | 归入"稳健复利"或"跨资产"研究 |
| **单边多头 / 杠杆贝塔** | 涨段大赚、跌段大亏 | 风险提示，不是趋势能力 |

### 2.3 一次成功不算能力

"宏观趋势捕捉"标签要求在 **≥ 3 个独立大波段**中都成立，并且显著优于基准（见第 5 节）。只抓住本轮的钱包，进入"异常行为与独特策略研究对象"，继续观察。

## 3. 三阶段方法

### 阶段一：收益曲线初筛（✅ 已实现）

- **数据**：B 层钱包的 portfolio allTime 曲线（已在采集，不额外消耗 API）。8–11 月期间相邻数据点的中位间隔约 1.9 天，足够切分大波段。
- **计算**：每个钱包在每个大波段内的资金流调整收益（波段两端 ±5 天内都要有数据点）；同期 BTC 涨跌幅；捕获比例。
- **运气概率**：假设每个波段赚钱的概率等于同行在该波段的赚钱比例，计算随机达到该战绩的概率（Poisson-binomial 分布）。
- **候选条件**：净值 ≥ $10k，没有噪声标记，不是子账户汇总；同时满足以下任一条：
  - 本轮涨段和跌段收益都 > 5%；
  - 在 ≥ 3 个波段中两个方向都赚过钱，且运气概率 < 0.05。
- **首轮实测**：3,875 个钱包算出了分段收益，291 个进入候选。本轮跌段（#16）只有 26% 的钱包赚钱，收益中位数为 −29.1%，和 BTC 跌幅几乎一样，说明大多数交易员一直是多头。

### 阶段二：用成交归因（数据已开始归档；计算待实现）

**数据抢救（✅ 已运行）**：候选钱包从 7/1 起的全部成交进入归档队列，每 10 分钟同步一批。API 只保留每个钱包最近约 1–2 万条成交（实测最多 21,280 条），高频钱包的 7–9 月成交已经无法取回，系统会标记"已截断"。

**待实现的计算**（`fill` 表 + 自记录 K 线）：

1. **净敞口路径**：每条成交都带 `startPosition`，所以不需要完整历史，也能精确知道每笔成交前后的仓位。
   `E(t) = Σ_coin 仓位(t) × 价格(t) / 净值(t)`，分别计算 BTC、ETH 和"主流币合计"三条路径。
2. **方向一致度**：波段内 `sign(E_BTC(t)) == 波段方向` 的时间占比，按 |E| 加权和不加权各算一份。
3. **建仓提前量**：净敞口首次以 ≥ 最大敞口 25% 的规模转到正确方向的时间，减去波段起点（单位：天；负数表示提前）。小波段（如 8/17 突破）单独计算。
4. **捕获比例**：`Σ E(t)·r_BTC(t) / (max|E| · 波段涨跌幅)`，即实际赚到的走势占"满仓拿住全程"的比例。
5. **持仓坚持度**：在 8/24–9/14 这类整理期里，是否保持方向和仓位。
6. **退出 / 反手质量**：在 9/21–10/2 双顶附近，敞口从多转为非多（或转空）的时间，以及当时价格离最高点的百分比；跌段同理看 11/15 附近。
7. **按币种的已实现盈亏**：每个波段内 BTC/ETH 和其他币种分别贡献了多少（候选页上的"BTC/ETH 已实现占比"就是简化版）。

### 阶段三：跨周期验证与标签

- 对 2025–2026 年的 16 个大波段逐一评估（早期波段只有收益曲线，没有成交时降级为"收益层面一致"）。
- **基准对照**：
  - 买入持有 BTC；
  - 简单趋势规则：20/50 日均线交叉，只用当时已有的数据；
  - **随机方向基准**：保持该钱包的敞口时间分布不变，把方向按区块随机打乱 1,000 次，得到"运气分布"；
  - 同层级同行的分布。
- **授予标签**：在 ≥ 3 个独立大波段中，方向一致度和捕获比例显著优于随机方向基准（p < 0.05）且优于趋势规则 → "宏观趋势捕捉（已验证）"。其他情况分别归入"潜力"或"研究对象"，并写明缺少哪些证据。

## 4. 事件敏感度（与大周期并行）

大周期看的是几周到几个月的方向；事件敏感度看的是**几小时到几天**的反应。

| 项目 | 设计 |
|---|---|
| 事件库 | 宏观数据（CPI、FOMC、非农）、加密行业事件（ETF 资金流、监管、交易所事故）、链上清算潮、HIP-3 标的的财报与商品事件。每个事件记录**可核实的公开时间**与来源，定义带版本 |
| 事件前异常仓位 | 事件前 T 小时内的仓位变化，相对该钱包自身过去 90 天同时段分布的 z-score；方向是否与随后走势一致 |
| 反应速度 | 事件公布后第一笔相关成交的延迟（分钟）、方向、规模 |
| 重复性 | 同一钱包在 ≥ 2 个**独立**事件中重复出现，才进入"事件前异常交易观察"名单 |
| 必须排除 | 公开信息已经发布；该钱包的常规策略本来就会在类似时点建仓；事后只挑赢家（必须同时统计同期所有类似仓位的钱包，包括亏损的） |
| 措辞 | 只使用"事件前异常仓位 / 异常领先行为 / 值得进一步研究"，**不说内幕、不推断身份、不暗示违法** |
| 数据 | 1 分钟 K 线从 2026-11-16 起开始自己记录（API 只保留约 3.5 天）。过去的事件用成交本身的价格加 15 分钟 / 1 小时 K 线近似 |

| **大周期页** `/swings` | ✅ | BTC 日线与大波段阴影图、各波段全体钱包表现、候选列表（波段战绩、运气概率、本轮涨跌两段收益、BTC/ETH 已实现占比、成交覆盖） |
| 交易员页"周期卡" | 阶段二 | 该钱包在每个波段的收益、方向一致度、捕获比例，以及与基准的对比 |
| **行情回放** | 阶段二 | 以时间轴展示价格、该钱包 BTC 净敞口（多绿空红）、每笔开平仓标记和事件标记；可以直接看出他是不是在 8/17 前已经在场、在 9/21 附近有没有减仓 |
| 关键价位交易 `/zones` | ✅ | 谁在 BTC 6 万多做多、谁在 8.4–8.8 万做空、谁两头都做对（见 09 第 1.2 节） |
| 顶部转向观察榜 | 阶段二 | 在 9/21–10/2 双顶前后 ±7 天内由净多转为净空的钱包，按反手时离最高点的距离排序 |
| 趋势高手持仓雷达 | 阶段三 | 已验证趋势交易员当前 BTC 净敞口的汇总（只做描述，不作为交易建议）；必须先做样本外检验，证明它有领先性才对外展示"信号"含义 |
| 反手提醒 | P2 | 已验证趋势交易员的 BTC 净敞口方向发生翻转时提醒（需要实时成交来源） |

## 6. 本轮新增的创新机会

| 名称 | 价值 | 所需数据 | 成本 | 优先级 |
|---|---|---|---|---|
| **K 顶部转向观察榜** | 直接回答"谁在 87k 附近转空"，是用户最关心的问题 | 候选成交（已在归档）+ 1h K 线 | 低 | **高** |
| **L 趋势高手共识指数** | 已验证趋势交易员的合计净敞口是否领先价格；如果样本外成立，就是独有的数据资产 | 阶段三的已验证名单 + 持仓快照 | 中 | 中（验证前不对外展示） |
| **M 宏观数据反应速度榜** | 衡量谁在 CPI / FOMC 公布后最快、最准地调整仓位 | 1m K 线（已开始记录）+ 实时或准实时成交 | 中 | 中 |
| **N 跨资产宏观交易员** | 实测发现大量盈利来自 HIP-3 原油、黄金、股票永续；这些交易员在加密分析工具里几乎没人研究 | 按资产类别归因的成交 + HIP-3 K 线 | 中 | 中 |

## 7. 局限与风险

| 局限 | 影响 | 应对 |
|---|---|---|
| API 成交窗口有限 | 高频钱包的早期成交已经丢失 | 已开始抢救性归档；标记"已截断"；长期依赖 S3 历史回填（P1 调研） |
| 收益曲线包含所有币种 | 第一阶段会把山寨币或 HIP-3 的盈利误当成 BTC 判断 | 阶段二按币种归因；候选页已经显示 BTC/ETH 已实现占比 |
| 子账户 | 主地址的曲线只是实体的一部分 | 子账户汇总钱包暂不进入候选；P1 合并子账户 |
| 幸存者偏差 | 跌段爆仓的钱包可能已经从排行榜消失 | 消失的钱包仍保留在库中参与统计 |
| 事后定义波段 | 波段终点是事后才知道的 | 只用于评估过去的行为；任何"信号"类功能必须只用当时可得的数据，并做样本外检验 |
| 小样本 | 一个周期只有两个大波段 | 标签要求 ≥ 3 个独立波段；运气概率与随机基准一起报告 |
