# 15 · 跟单升级与交易员分析（M4）

## 模拟跟单

| 功能 | 说明 |
|---|---|
| 按比例跟单 | 你的开仓金额 = 跟单比例 ×（交易员开仓金额 ÷ 交易员账户余额）× 你的账户余额。`size_factor` 就是比例（1 = 100%），表单以百分比输入，有 50/100/200% 快捷键和实时算例 |
| 杠杆模式 `leverage_mode` | `account`：全仓，总敞口 ≤ 最高杠杆 × 净值，账户维持保证金不足整体强平并停止。`leader`：逐仓，每个仓位用交易员在该币的杠杆（≤ 最高杠杆、≤ 币种上限），保证金 = 名义 ÷ 杠杆，强平价 = 开仓价 × (1 ∓ 1/L ± mmr)，mmr = 1/(2 × 币种最大杠杆)；单仓强平只损失该仓保证金，模拟继续，且不再追同一笔交易员仓位 |
| 镜像交易员强平 | 交易员某币仓位消失时价格已在他上一轮报告的强平价 0.5% 以内或越过 → 记为 `leader_liquidated`（推断）；逐仓模式按强平处理 |
| 持仓最大浮亏（MAE） | `sim_position.worst_upnl / best_upnl` 每轮更新；平仓那笔 `sim_trade.mae` 记录该仓位持有期间的最大未实现亏损 |
| 统计 | 每个周期：最大回撤、最长水下天数、当前回撤、最差浮亏、强平次数；列表页有冠军卡、排序（收益 / 盈亏 / 回撤 / 保留率 / 收益÷回撤）和按交易员汇总 |

## 历史回测跟单（`app/sim/backtest.py`）

复用实时引擎的 `target_sizes / plan_orders / fill`。按交易员每次决策的真实时间 + 延迟，用当时最细的 K 线开盘价成交（1m → 5m → 15m → 1h；币安 → OKX → Hyperliquid），Hyperliquid 无延迟时用他自己的成交均价。每小时按最高/最低价检查强平。交易员净值：Hyperliquid 用账户历史；OKX 用当前带单资产（近似），没有则不回测。资金费不计；OKX 只有整笔仓位，跟单者吃不到中途加减仓。`capped_share` 报告按比例会超过最高杠杆的占比。

接口：`GET /api/v1/wallets/{a}/backtest?days&ratio&delay&leverage_mode&capital`（决策 ≤ 3000 时同时算延迟敏感度：0 / 30 秒 / 5 分 / 30 分 / 2 小时）。

## 每日批量（worker `copy_analysis`，01:00 UTC；错过一晚时，服务启动约 20 分钟后补跑）

1. 候选池（≤ 600）：收藏、模拟中、风格 verified/candidate、节奏显著、OKX 7 天在榜，且 90 天内有交易。
2. 默认设置（1 万、100%、30 秒延迟、4.5bp + 3bp、10x、全仓）回测 7 / 30 / 90 天 → `copy_backtest`；30 天附延迟曲线。
3. 可跟单性评分 `copy_score`（`app/factors/copyability.py`）：实力 20、回测收益 20、回撤 15、强平与杠杆 15、延迟敏感度 15、样本与活跃 10、集中度 5；A ≥ 80 / B ≥ 65 / C ≥ 50；已平 < 15 或无回测 → 数据不足。
4. 状态 `trader_health`（`app/factors/health.py`）：近 30 天 vs 此前 180 天 → 沉寂 / 走下坡 / 风格漂移 / 近期火热 / 稳定 / 样本不足；收藏、订阅或模拟中的交易员变差时合并发一封邮件，并进入每日简报。
5. 评分存档与前瞻检验（`app/factors/copy_validation.py`，迁移 0025）：每个 UTC 日的评分冻结进 `copy_score_history`，有了随后结果的那天不再改写。评分后满 7 天、30 天，用同一套默认设置回放此后的跟单收益，写入 `copy_score_outcome`；期间没有决策的记为 0，缺权益等无法回放的记原因、不计入。检验只在同一评分日内比较排名（Spearman），评分日之间至少间隔一个周期，满 8 个评分日后做单侧符号翻转置换检验。结果见 `/copy-board` 底部“评分可信度”，接口 `GET /api/v1/copy-board/validation`。迁移时以当时的 `copy_score` 作为第一天存档。
6. 历史持续性（每周日 UTC 03:30，子进程，迁移 0027 `copy_persistence_run`）：跟单收益榜按过去收益排名，这里检验排名能否延续。按交易所，每隔 7 天（或 30 天）取一个日期，从当时 30 天内至少有 5 次决策的交易员中按哈希随机抽 300 人，用默认设置回放日期前 30 天和之后 7 / 30 天的跟单收益，同日内做 Spearman，并比较前 1/5 与后 1/5 的后续收益；日期之间的后续窗口不重叠，满 8 个日期后对各日相关系数做单侧符号翻转检验。每次最多取最近 40 个日期。样本只含现在仍在档案里的交易员（幸存者偏差）。
   - 方法版本 2：Hyperliquid 的历史回放按资产点自身时间使用归档的账户历史（`backtest(..., history=True)`）。账户价值在链上实时公开，跟单者当时即可据此定仓；严格模式（按本系统采集时间）仍用于实时和前向场景。归档的账户历史 2026-11-15 起才采集，严格模式下更早的日期全部是“无权益”。
   - OKX 回测在两个窗口都用当前带单资产作分母。赚钱的交易员因此在收益排名上显得有持续性（单测中用无持续性的模拟数据复现了显著的假阳性），所以 OKX 的结论只看方向一致性：过去为正与之后为正的相关，在各日期上做同样的符号翻转检验。共用分母只改变大小，不改变正负。
   - 结果带方法版本号；版本变化时，部署后约 45 分钟自动重算，不必等到周日。

## 行为指纹（`app/research/behavior.py`，`GET /api/v1/wallets/{a}/behavior`）

开仓星期 × 小时热力图；盈利仓 vs 亏损仓持仓时长；死扛亏损 / 让利润奔跑、偶有巨亏 / 止损干脆、亏损后加码、摊平亏损（仅 Hyperliquid）、仓位变大、杠杆变高（OKX）、最长连胜连亏。每个标签需 ≥ 10 个样本。
