# 11 · OKX 数据源

> 目标：把 OKX 带单交易员作为第二个数据源接进来。研究、收藏、提醒、模拟跟单和看板都共用一套，只是数据来源不同。OKX 能公开拿到每个带单员 1–2 年的完整历史仓位，下榜的人历史也还在，是验证"大周期、拿得住"最好的样本库。

## 1. 数据从哪来（2026-11-16 实测）

| 接口 | 内容 | 用途 |
|---|---|---|
| `priapi/v5/content/public/community/leaderboard` | 7 / 30 / 90 / 365 天带单榜（按收益率），每页最多 50 人，带 `dataVersion`、`total`、`pages` | 每日发现新交易员、上榜记录 |
| `priapi/v5/content/public/user-info?authorId=` | 资料，含 `uniqueName` | 榜单只给 authorId，历史仓位接口要 uniqueName |
| `priapi/v5/ecotrade/public/community/user/position-history` | 已平仓仓位，`limit` 最多 100，`after` = 上一页最早一条的 uTime（毫秒），按 uTime 倒序 | 历史仓位回填与增量 |
| `.../user/position-current` | 当前持仓（按币种分组的 posData） | 实时提醒、模拟跟单 |
| `.../user/asset` | 带单资产 | 按净值比例跟单、排序 |
| `api/v5/public/instruments`、`market/tickers`、`public/funding-rate`、`market/history-candles` | 合约规格、价格、资金费率、K 线 | 张数换算、实时价格、模拟成本、只在 OKX 交易的币种的 K 线 |

- **访问**：服务器（194.163.135.37）可以直接访问，每个请求约 0.3 秒；每秒 3 次连续请求没有被限流。默认预算是 worker 每分钟 120 次，实时进程另有每分钟 60 次。
- **主页链接**：`https://www.okx.com/zh-hans/copy-trading/account/<uniqueName>`。

## 2. 和 Hyperliquid 的区别

OKX 公开的是**完整仓位**：开仓时间与均价、平仓时间与均价、最大仓位、盈亏、手续费、资金费、杠杆、是否强平。它没有逐笔成交。

| 方面 | 影响 |
|---|---|
| 历史长度 | 1–2 年，Hyperliquid 只有约 4 个月 → OKX 更适合"已验证"层 |
| 加减仓时点 | 看不到；开仓均价包含了后来的加仓 → 节奏评分不计 15 分钟级别 |
| 仓位路径 | 近似为"开仓到平仓一直持有最大仓位" → 整段行情捕获率是近似值 |
| 同币多仓 | 双向持仓或多个逐仓可以同时存在 → 按币种汇总净仓位（实时监控、模拟跟单和行情捕获都这样处理） |
| 盈亏口径 | 直接用 OKX 的 `realizedPnl`，它含资金费和强平罚金；手续费单独记录 |

**换算**：
- 线性合约（USDT/USDC 保证金）：数量 = 张数 × ctVal 个币，盈亏单位是 USD。
- 反向合约（`-USD-SWAP`）：一张 = ctVal 美元，盈亏单位是币，按平仓价换成 USD。
- `closeAmount` 是这个仓位一生中累计平掉的张数：交易员减仓后又加仓时，它会大于 `openMaxAmount`。OKX 的盈亏按它计算，所以它就是开仓、平仓两个决策的成交量。

## 3. 数据模型（迁移 0009）

交易员实体通用化：

- **`wallet` 增加字段**：`venue`（hyperliquid / okx）、`venue_uid`（OKX authorId）、`handle`（uniqueName）、`avatar_url`。
- **交易员键**：Hyperliquid 是地址 `0x…`，OKX 是 `okx:<authorId>`。用 authorId 而不用 uniqueName，因为旧数据里有 399 人只有 authorId。
- **复用**：收藏、提醒、模拟、节奏评分、波段持仓者、K 线回放都挂在 `wallet.id` 上，不用改表。
- **`present_in_latest`**：只表示"在 Hyperliquid 当前榜单上"。OKX 交易员恒为 false，所以分层、增强等 Hyperliquid 专用流程天然跳过他们。

新增的表：

| 表 | 说明 |
|---|---|
| `okx_position` | 一条已平仓（或部分平仓）的仓位：USD 与币数两套口径、原始记录 jsonb |
| `okx_trader` | 每个交易员的回填状态（partial / target_complete / source_complete / error_backoff）、游标、跟踪状态（active / watching / dropped / inactive）、优先级、资产、资料 |
| `okx_leaderboard_run` / `okx_leaderboard_row` | 每次抓榜及每个人的名次和官方数据 |
| `okx_presence` | 上榜天数、连续天数、最好名次、是否在榜（按业务日，北京时间） |
| `okx_instrument` | 合约规格：ctVal、线性 / 反向、最大杠杆 |
| `market_candle`（source=okx） | 只在 OKX 交易的币种的 1h / 4h / 1d K 线 |

**派生**（`app/okx/positions.py`）：每条仓位生成 1 个 `position_cycle`（version `okx1`）和 2 个 `trade_decision`（开仓、平仓）。部分平仓的仓位是"持仓中"的周期，只有开仓决策。周期的 `realized_pnl − fees` 等于 OKX 报告的已实现盈亏。

## 4. 采集（worker）

| 任务 | 频率 | 内容 |
|---|---|---|
| `okx_daily` | 每 30 分钟检查一次 | 北京时间 08:30 后，如果今天还没有完整的 7 天榜，就完整抓一次；30 / 90 / 365 天榜抓前 2 页 |
| `okx_history` | 每 5 分钟 | 每批 60 人，每人每次最多 30 页 |
| `okx_upkeep` | 每小时 | 补 uniqueName（每次 50 人）；活跃和重点关注交易员的资产（超过 1 天才刷新）；合约规格 |
| `okx_candles` | 每 15 分钟 | 只在 OKX 交易的币种的 K 线，每次最多 300 个请求 |

**7 天榜的完整性校验**（沿用旧采集器，满足全部条件才算完成）：

- 每一页的 `dataVersion` 和总人数都与第 1 页相同；
- 页数等于 ⌈总人数 / 每页人数⌉，每页人数正确；
- 没有重复的人；
- 抓完后复核第 1 页没有变化；
- 去重后的人数等于官方总人数。

如果中途发现榜单已经重新发布，整轮重抓，最多 3 次。只抓了部分页的长周期榜只增加上榜记录，不会把没抓到的人标成下榜。

**历史仓位**：

- **回填**：从游标往更早的方向翻页，直到覆盖 365 天，或者官方再也没有更早的数据。空页或不满一页时会再请求一次确认。
- **增量**：从最新一页往下读，直到碰到已经入库的仓位。部分平仓的仓位全部平掉后会重新出现在最前面，入库时直接更新。
- **频率**：活跃和重点关注的人每小时一次，不活跃的每天一次，已下榜的每周一次。
- **出错**：指数退避，最长 1 小时，已有状态保留。

**优先级**：

| 优先级 | 交易员 |
|---|---|
| 0 | 收藏或模拟跟单中的 |
| 1 | 新上榜的 |
| 2 | 在榜上的 |
| 3 | 其他 |

同一优先级内，先回填、后增量。

**跟踪状态**：在任何榜上出现就是 active；7 天没出现在任何榜上就变成 dropped。收藏或跟单会把已下榜的人改成 watching。

## 5. 研究复用

- **节奏评分**：OKX 交易员和 Hyperliquid 钱包一起计算，Benjamini–Hochberg 多重检验校正也一起做。15 分钟级别的决策标记为 `coarse`，不计分。
- **K 线**：优先级是币安 → Hyperliquid → OKX。
- **波段持仓者**：OKX 的持仓中周期是真实的持仓，不是数据截止造成的。
- **关键价位**：覆盖统计同时计入 Hyperliquid 的成交归档和 OKX 的历史仓位。
- **整段行情捕获率**：OKX 用"累加每个决策的仓位变化"得到净仓位路径。
- **交易所切换**：排行榜、节奏榜、波段持仓者、关键价位页面都有切换按钮，选择记在 cookie 里，所有链接和表单都会沿用。排行榜切到 OKX 时显示：当日榜单（官方数据 + 我们算的已实现盈亏、强平次数、节奏超额）、今日新上榜、已下榜但历史完整的交易员。

## 6. 实时提醒与模拟跟单

- **监控对象**：实时进程每 60 秒（设置页可改，最少 30 秒）轮询一次被订阅或被模拟跟随的 OKX 交易员，使用自己的请求预算。
- **每轮请求**：
  - 1 次 tickers，取所有 USDT 永续的中间价；
  - 每人 1 次 position-current，按合约规格把张数换算成币数，再按币种汇总成净仓位。
- **复用**：仓位变化的识别、邮件合并、免打扰和限流都用 Hyperliquid 那一套（`apply_snapshot`）。
- **资产**：用 `okx_trader.asset`。在榜的人每天从榜单更新，其他活跃和重点关注的人每天调用资产接口更新。
- **模拟引擎**：`step_simulations(venue=…)` 只处理跟随该交易所交易员的模拟，用该交易所的价格成交。
  - 资金费率：OKX 返回的费率按结算周期（8 / 4 / 1 小时）换算成每小时费率，只查询模拟中涉及的币种。
  - 最大杠杆：取自 `okx_instrument`。
  - 手续费：建议填 5 bp（OKX 吃单费率）。

## 7. 一次性迁移旧采集器

```bash
# 本机（只读打开 SQLite）
python -m app.cli okx-export --sqlite ~/Documents/欧意排行榜/okx_rankings.sqlite3 --out okx_bundle/
# 服务器（可以重复执行）
python -m app.cli okx-import --bundle okx_bundle/
```

- **数据量**：交易员 2,629 人；仓位 85.8 万条（另有 265 条交割合约被跳过）；33 次完整的每日 7 天榜；上榜记录 5,245 条；收藏 36 个（导入到"OKX·"开头的分组，加 `okx` 标签）；K 线 79.7 万根。
- **耗时**：本机导出 45 秒、打包 107 MB；导入加派生约 4 分钟。
- **校验**：抽查 5 人，仓位数、价格盈亏、已实现盈亏、首末时间、强平次数和 SQLite 完全一致。
- **旧项目**：导入后停用，SQLite 文件保留作为备份。
- **不迁移**：旧项目的评分榜（综合总榜、趋势增强榜 TQS 等），OKX 只用本系统的评分体系。

## 8. 已知限制

- priapi 是网页内部接口，没有文档，随时可能改。所有返回都会校验结构，异常时直接报错，不会写入半懂的数据。
- 只覆盖永续合约（SWAP），交割合约和现货看不到。
- 带单资产只是带单账户的资金，不一定是交易员的全部资金。
- 双向持仓汇总成净仓位后，接近强平的判断用占比最大的那一笔仓位的强平价。
